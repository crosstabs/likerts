SDK 0.0.3 · CLI 0.1.2

Collect a response inside your product.

Your application owns the moment. Likerts supplies the survey contract, rendering SDKs and collection API.

Developer preview. Invitation-only access, no SLA and test-mode payments. The one-time free grant is 1,000 accepted responses per eligible verified workspace. See current boundaries before using real customer data.
01 / First responseCreate, publish and collect.02 / Try the rendererLocal sample. No account needed.03 / API referenceOperations, scopes and inputs.

The workflow is survey draft → published version → collection → accepted response. A collection binds an immutable survey version to a placement in your app. Respondents do not need a Likerts account.

Two credentials serve different jobs: your server, CLI or agent uses a management credential; your embedded SDK uses a collection credential limited to one collection. Never ship a management credential in a browser or mobile bundle.

Get your first accepted response.

This complete CLI path uses a synthetic sample answer. It consumes one free or paid response credit when accepted by the real backend. For a zero-network walkthrough, use the local SDK demo instead.

1. Open your workspace

Open the developer preview and complete passwordless email verification. Create a scoped service credential in your workspace and supply its token to your shell through your secret manager as LIKERTS_TOKEN. Copy the workspace ID for remote MCP. The quickstart needs surveys:read, surveys:write, collections:write, responses:read and usage:read; export and cleanup steps below require their separately noted scopes.

Credentials expire after 90 days and are shown once. Revoke lost or unused credentials in the workspace. Do not paste credentials into an agent conversation or commit them to source control.

2. Install the CLI

Use the source path below on supported Rust hosts; it requires Rust/Cargo, curl, jq and a SHA-256 utility. Apple Silicon macOS also has a native archive. The native executable is unsigned and not notarized; use source installation if your macOS policy blocks it.

shell
curl --fail --remote-name https://likerts.com/downloads/likerts-cli-source-0.1.2.tar.gz
curl --fail --remote-name https://likerts.com/downloads/SHA256SUMS
awk '/likerts-cli-source-0.1.2.tar.gz$/' SHA256SUMS | shasum -a 256 -c -
tar -xzf likerts-cli-source-0.1.2.tar.gz
cargo install --locked --path tools/cli
export LIKERTS_API_URL=https://likerts-api.onrender.com
# LIKERTS_TOKEN is already supplied by your secret manager.
likerts call usage_get
Apple Silicon macOS native installation (optional)

Only aarch64-apple-darwin is provided as a native binary. This does not cover Intel Macs, Linux or Windows; use the Cargo source path for other supported Rust hosts.

shell
curl --fail --remote-name https://likerts.com/downloads/likerts-cli-0.1.2-aarch64-apple-darwin.tar.gz
curl --fail --remote-name https://likerts.com/downloads/SHA256SUMS
awk '/likerts-cli-0.1.2-aarch64-apple-darwin.tar.gz$/' SHA256SUMS | shasum -a 256 -c -
tar -xzf likerts-cli-0.1.2-aarch64-apple-darwin.tar.gz
./likerts --version
mkdir -p "$HOME/.local/bin"
install -m 755 ./likerts "$HOME/.local/bin/likerts"
export PATH="$HOME/.local/bin:$PATH"

After installation, set LIKERTS_API_URL and provide LIKERTS_TOKEN as shown above. The native and source builds expose the same 41-operation registry.

3. Create and publish

The commands save request files so an ambiguous retry can reuse the identical request and idempotency key. Keep this directory private; collection creation writes a credential to collection.json. Use a new idempotency key only for a new intended operation.

shell
umask 077
mkdir -p likerts-quickstart
cd likerts-quickstart
curl --fail https://likerts.com/docs/survey-create.json -o survey-create.json
curl --fail https://likerts.com/docs/sdk-capabilities.json -o sdk-capabilities.json
likerts call surveys_create --input survey-create.json > survey.json
jq --slurpfile caps sdk-capabilities.json   '{id: .id, revision: .revision, sdkCapabilities: $caps[0]}' survey.json > publish.json
likerts call surveys_publish --input publish.json > published.json

View the actual create request. The capability file describes Web 0.0.3 only. Replace it with the exported capability records of every SDK installation group your product actually uses, including older versions still installed.

4. Open a collection

shell
jq --slurpfile caps sdk-capabilities.json   '{idempotencyKey: "docs-collection-001", surveyId: .surveyId,
    version: .version, placement: "quickstart", responseCap: 10,
    sdkCapabilities: $caps[0]}' published.json > collection-create.json
likerts call collections_create --input collection-create.json > collection.json
export LIKERTS_COLLECTION_TOKEN="$(jq -r .token collection.json)"

5. Send one sample response

shell
jq '{id: .id, idempotencyKey: "docs-response-001",
  answers: {rating: 5}, metadata: {channel: "quickstart"}}'   collection.json > response.json
likerts call responses_submit --input response.json > receipt.json
cat receipt.json
likerts call usage_get

The returned receipt identifies the accepted response. Repeating the exact request returns the prior receipt without using another credit. The receipt's chargedCents: 1 is the response unit; the ledger consumes promotional credits first. Do not change answers while reusing a key.

Next: embed the Web SDK, choose another platform below, or read back your response.

Web

Use a modern browser with Fetch, AbortController and crypto.randomUUID. The package contains compiled ESM and TypeScript definitions; bundle it in your application. Public npm registry installation is not available yet.

shell
curl --fail --remote-name https://likerts.com/downloads/likerts-web-0.0.3.tgz
curl --fail --remote-name https://likerts.com/downloads/SHA256SUMS
awk '/likerts-web-0.0.3.tgz$/' SHA256SUMS | shasum -a 256 -c -
npm install ./likerts-web-0.0.3.tgz

Add a <div id="feedback"></div> in your product, then call this after your own eligibility and consent checks. Obtain the collection ID and collection-only token from your setup flow; the placeholders below must be replaced.

JavaScript
import { LikertsClient, mountSurvey, LIKERTS_SDK_CAPABILITY } from '@likerts/web';

const client = new LikertsClient(
  'https://likerts-api.onrender.com',
  'YOUR_COLLECTION_ONLY_TOKEN',
);
const collection = await client.collection('YOUR_COLLECTION_ID');
const cleanup = mountSurvey(
  document.querySelector('#feedback'), collection, client,
  receipt => console.log(receipt.responseId),
  { screen: 'receipt' },
  { messages: { submit: 'Send feedback', submitted: 'Thank you' } },
);
// Call cleanup() on navigation or dismissal.
// Report LIKERTS_SDK_CAPABILITY to your publishing/collection setup.

For cross-origin calls, configure your exact browser origin first. Style the stable likerts-* classes using external CSS. The SDK inserts no inline style. A collection configuration is cached for five minutes; use client.collection(id, {refresh: true}) before presentation when a fresh fetch is required. Call client.clearCollectionCache() on lifecycle teardown.

const client = new LikertsClient(API_ORIGIN, collectionOnlyToken);
<SurveyHost

Connect Codex or Claude Code.

The documented preview path uses a workspace-bound service credential. It is separate from provider OAuth, whose end-to-end customer consent/refresh/revocation acceptance is pending. Grant only needed capabilities. The gateway exposes the tool registry; unauthorized calls are denied by the API even if a tool remains discoverable.

Set LIKERTS_WORKSPACE_ID to the workspace ID displayed in the app. Supply LIKERTS_TOKEN through the client process environment using your secret manager. The token must belong to that same workspace.

Codex CLI

shell
codex mcp add likerts   --url "https://likerts-mcp.onrender.com/mcp/$LIKERTS_WORKSPACE_ID"   --bearer-token-env-var LIKERTS_TOKEN

Claude Code

Merge this entry into your project's .mcp.json. Replace YOUR_WORKSPACE_ID; keep the token as an environment reference. Start Claude Code with that environment supplied. Other Claude products may have different connector support. See the official Claude Code environment-variable documentation.

JSON
{
  "mcpServers": {
    "likerts": {
      "type": "http",
      "url": "https://likerts-mcp.onrender.com/mcp/YOUR_WORKSPACE_ID",
      "headers": { "Authorization": "Bearer ${LIKERTS_TOKEN}" }
    }

First ask the agent to call usage_get with {}. Creating, publishing and collecting use the same input objects as the CLI; id fields identify path resources. Keep keys outside model tool arguments. Collection creation returns a limited collection token, so handle that result accordingly. A real fresh-customer connection in each client is still a release acceptance gate; these instructions describe the implemented service-token transport.

Remove an integration by revoking its service credential in your workspace and removing the client configuration. likerts auth logout manages separately stored OAuth credentials; it does not revoke an environment service token.

Use the HTTP API directly.

The production API origin is https://likerts-api.onrender.com. Management calls use a bearer service credential already bound to one workspace. A separately configured human OAuth call also selects a workspace with X-Likerts-Workspace; the server still checks membership and scope.

shell
export LIKERTS_API_URL=https://likerts-api.onrender.com
# LIKERTS_TOKEN is supplied by your secret manager.
printf 'header = "Authorization: Bearer %s"\n' "$LIKERTS_TOKEN" |   curl --fail-with-body --config - "$LIKERTS_API_URL/v1/usage"

This reads the header from stdin to avoid placing the token in curl's process arguments. Collection schema/submission endpoints instead use the collection credential. Never interchange the two. See the operation reference for scopes and routes and OpenAPI JSON for authoritative input/output schemas.

HTTPS is required except on exact loopback development hosts. SDKs and management tools refuse redirects. Do not place tokens in URL query strings. Keep customer answers out of application logs and agent prompts unless explicitly intended and authorized.

Retrieve and export responses.

Continue in the private directory from the quickstart. Reading requires responses:read. Response listing uses stable cursor pagination; a new request without a cursor starts a fresh snapshot.

shell
jq '{collectionId: .id, limit: 100}' collection.json > list.json
likerts call responses_list --input list.json > responses.json
cat responses.json
# If nextCursor is not null, reuse the filter with that cursor:
jq --slurpfile page responses.json '. + {cursor: $page[0].nextCursor}'   list.json > next-page.json
# Run only when nextCursor is not null:
# likerts call responses_list --input next-page.json

Export creation/revocation requires exports:write; job lookup/download requires exports:read. A JSON or CSV export is an asynchronous snapshot. Poll its ID until the status is ready; handle failed, expiry or revocation rather than polling forever.

shell
jq '{idempotencyKey: "docs-export-001", format: "json", collectionId: .id}'   collection.json > export-create.json
likerts call exports_create --input export-create.json > export-job.json
jq '{id: .id}' export-job.json > export-id.json
likerts call exports_get --input export-id.json
# After status becomes "ready":
likerts call exports_download --input export-id.json > export-download.json
shell
# Decode and verify the downloaded JSON without printing response content.
python3 - <<'VERIFY'
import base64, hashlib, json
from pathlib import Path
bundle = json.loads(Path('export-download.json').read_text())
body = base64.b64decode(bundle['contentBase64'], validate=True)
assert hashlib.sha256(body).hexdigest() == bundle['contentSha256']
Path('responses-export.json').write_bytes(body)
print('Export checksum verified')
VERIFY

Export jobs and downloads expire after 24 hours. Keep downloaded files in your own protected storage and apply your retention policy. Revoking a server export cannot erase a copy you already downloaded.

Clean up the sample.

These commands delete the sample response and revoke its export. They are intentional data-changing actions; inspect the saved IDs before running. Deletion does not undo accepted usage or create a refund. Delete local exported copies separately when finished.

shell
# Requires responses:write. Verify receipt.json contains your sample response.
jq '{id: .responseId}' receipt.json > response-delete.json
likerts call responses_delete --input response-delete.json

# Requires exports:write. Verify export-id.json identifies your sample export.
likerts call exports_revoke --input export-id.json

# Stop this collection accepting new submissions (collections:write).
jq '{id: .id, accepting: false}' collection.json > collection-stop.json
likerts call collections_update --input collection-stop.json
unset LIKERTS_COLLECTION_TOKEN

Revoke the management credential in the workspace when no longer needed. Remove the private sample directory and its collection token using your normal secure cleanup process. Workspace deletion and retention operations are documented separately in the API reference; do not run them as casual quickstart cleanup.

Receive credit threshold notifications.

Subscribe your own HTTPS receiver to credits.threshold_reached to react when a credit bucket crosses 80%, 90% or 100% depletion. Creating or enabling this subscription needs both webhooks:write and usage:read; human OAuth also requires workspace ownership. Read delivery status with webhooks:read.

Replace the example URL with your receiver. Creation returns a disabled endpoint. Keep its returned signingSecret private, install that secret and endpoint.keyId on your receiver, then enable it. The example saves the secret-bearing response to a private file; do not commit or share that file.

shell
umask 077
cat > credit-webhook.json <<'JSON'
{
  "idempotencyKey": "credit-alerts-001",
  "url": "https://hooks.example.com/likerts",
  "eventTypes": ["credits.threshold_reached"]
}
JSON
likerts call webhook_endpoints_create --input credit-webhook.json > webhook-private.json

Pause here: install the returned endpoint.keyId and signingSecret in your receiver, and verify it is ready to validate signed requests. Only then run the separate enable step:

shell — after receiver setup
jq '{id: .endpoint.id, enabled: true}' webhook-private.json > webhook-enable.json
likerts call webhook_endpoints_update --input webhook-enable.json

Verify the exact raw bytes before parsing: Likerts-Signature contains t=UNIX_SECONDS,kid=KEY_ID,v1=HEX_MAC. Compute HMAC-SHA256 with the literal UTF-8 signing secret over timestamp + "." + eventId + "." + rawBodyBytes, compare in constant time, allow at most five minutes of clock skew and require the body ID to match Likerts-Event-Id. Deduplicate by event ID; acknowledge only after safely recording receipt.

Promotional and paid balances have separate generations. An increase in a bucket's available, nonnegative balance starts that bucket's next generation. Later depletion produces each 80%, 90% and 100% threshold once in that generation. Refunds, reversals and corrections can also deplete a balance: a notification does not mean that percentage was spent on responses. A paid top-up does not reset promotional alerts.

Only future crossings while an opted-in endpoint is enabled are delivered; there is no historical backfill. Events can arrive out of order or after a top-up, so retrieve usage_get when enabling and receiving them. The payload contains identifiers, bucket, generation and threshold, with no answers or balance amounts. Your receiver decides how to notify your team; Likerts does not send email or SMS for these events.

Existing endpoints default to response.accepted; credit events require the explicit subscription above. URL and event subscriptions are immutable: create a new endpoint to change them. See creation, delivery inspection and bounded replay in the API reference. Hosted delivery acceptance is a separate release check.

One question contract, five renderers.

Survey definitions use nine bounded types. Answers are keyed by stable question IDs. Required answers must be present; unknown IDs and out-of-range values are rejected. Omit an optional answer rather than sending JSON null.

TypeAnswer
scaleInteger between min and max; Likert labels and NPS are optional presets/configuration.
single_choiceOption ID (or structured choice representation when Other is enabled).
multiple_choiceUnique option IDs, respecting selection limits and exclusive None.
text / number / dateBounded text, numeric value, or calendar date string.
rankingA complete option-ID permutation.
matrixRow IDs mapped to one column ID or a nonempty array of column IDs.
constant_sumEvery item ID mapped to a nonnegative integer; sum equals the configured total.

Conditional visibility allows one predicate: equals, not_equals, includes, not_includes, answered or not_answered. It does not support arbitrary expressions, nested Boolean logic or range comparisons. Hidden answers are pruned; hidden required questions are not required. Page branches move through the declared bounded flow.

Publication and collection creation must declare every distinct installed SDK group. Report the exported capability record, not just your newest version. The backend blocks a survey schema that any declared group cannot render. Web 0.0.3 supports schemas 1–5; older artifacts differ.

Download real schema examples: baseline, labeled scales/NPS, Other/None/stars, conditional visibility, pages/branches, ranking/matrix/constant sum. These are draft definitions; add a stable idempotencyKey for survey creation.

Allow your browser origin.

For a direct browser integration, update the collection's exact HTTPS origins using a management credential with collections:write. Replace the sample hostname with your app's real origin. This requires no respondent account; the collection token still enforces collection binding, expiry, caps and revocation.

shell
jq '{id: .id, allowedOrigins: ["https://your-app.example"],
  requestsPerMinute: 6000}' collection.json > collection-security.json
likerts call collections_security_update --input collection-security.json

An origin is browser policy, not authentication or a promise that a credential cannot be copied. Do not use wildcard origins. A same-origin proxy is another integration choice; keep its upstream fixed and validate your own request boundaries. A strict Content Security Policy must allow the API origin in connect-src, and the SDK/CSS assets in your own script/style rules.

Errors, retries and version changes.

Keep the exact immutable submission and key after an ambiguous timeout/network failure. Reusing that key with changed answers is a conflict. A receipt proves acceptance; a local queue entry or spinning UI does not.

OutcomeHost action
400Fix invalid fields against the published schema; do not blindly retry.
401 / 403Check credential type, expiry, scope and revocation. Never replace a collection token with a management token in the client.
404 / 410Stop the unavailable/deleted/expired collection and surface a safe state.
409Inspect revision/idempotency or compatibility conflict. Preserve the original request while resolving ambiguity.
408 / 425 / 429 / 5xx / network failureRetry under your host's bounded policy, preserving the submission. Honor Retry-After when provided; do not spin in an unlimited loop.
Balance or configured cap exhaustedPause new collection attempts and inspect workspace usage/blocking reason. No automatic charge is implied.

The management CLI makes no automatic write retries. Web client defaults are a 15-second timeout and 256 KiB response-body limit. Cancel requests on dismissal. A published version is immutable; update the draft and publish a new version for subsequent collections. Keep older SDK installation groups in your capability declaration until they are genuinely retired.

Offline storage is host-controlled.

The optional offline queue does not silently intercept ordinary submissions or run a background scheduler. Your app explicitly enqueues an immutable submission and calls flush when lifecycle/connectivity policy allows. Local enqueue is not server acceptance and uses no response credit.

Defaults: 1,000 records, 10 MiB encoded payload, seven days; bounded ceilings are 10,000 records, 100 MiB and 30 days. A record is limited to 64 KiB. Full queues reject new items instead of evicting unanswered data. Successful receipts remove records; retryable failures remain pending; terminal failures stay blocked until deletion or local expiry.

PlatformStorage / key
WebEncrypted IndexedDB records; non-extractable WebCrypto key in IndexedDB.
React NativeRequired native queue adapter backed by Keychain/Keystore; no plaintext fallback.
iOSApplication-support file/SQLite; device-only Keychain AES-GCM key.
AndroidPrivate file/Room; non-exportable Android Keystore AES-GCM key.
FlutterNative platform adapter using the same iOS/Android key profiles.

Collection tokens are resolved at flush time and are not persisted in queue records. Your host handles Retry-After scheduling, cancellation, maximum age, logout cleanup and native backup exclusions. Browser encryption does not protect against malicious scripts executing in the same origin; no queue promises delivery, cross-device sync or recovery after key loss.

What this preview does and does not prove.

The supported preview distribution is checksummed direct archives, currently SDK 0.0.3 and CLI source 0.1.2. Package registries are pending. UI/schema tests and selected simulator/emulator checks exist; full browser, screen-reader and physical-device acceptance is ongoing.

Fresh-user onboarding, real Codex/Claude customer acceptance, live payments and managed operational recovery remain launch gates. There is no SLA, dedicated-tenancy promise or enterprise SSO claim. Public support, privacy, credit/refund and subprocessor policies are awaiting owner review; do not infer terms from this technical guide.

Survey placement, consent, eligibility, surrounding copy, distribution and downstream data use remain your responsibility. Likerts does not send survey emails or host campaign links. The sample demo never submits responses; this guide's real backend quickstart does.

The service status page reports current dependency checks. Inspect the control-plane configuration check for configuration presence only. It is not an uptime monitor or incident history.
