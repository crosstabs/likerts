# Likerts capability reference

Generated by `node contracts/generate-examples.mjs`. Examples use synthetic IDs and tokens and are independent illustrations. Replace IDs with returned resources, choose a future credential expiry and inspect destructive operations before calling them.

Set `LIKERTS_API_URL` to your API origin. Management calls use `LIKERTS_TOKEN`, or the CLI’s stored passwordless OAuth login; human OAuth also requires `LIKERTS_WORKSPACE_ID`. Collection calls use `LIKERTS_COLLECTION_TOKEN`. The API takes the corresponding bearer token and, for human OAuth, the `X-Likerts-Workspace` header. Credentials never belong in input JSON.

Run any example with `likerts call OPERATION --input contracts/examples/OPERATION.input.json`. MCP uses the same operation name and the JSON file contents as `arguments`. API bodies omit path fields such as `id`; GET inputs become query parameters. Successful CLI/MCP text output is the API JSON body; HTTP 204 becomes `{}`. MCP also publishes a typed `outputSchema` and returns `structuredContent: {result: ...}`.

## Errors and retries

Direct API errors have `{error:{code,message}}`; [error-codes.json](error-codes.json) lists stable codes by status. All operation schemas document authorization failures, domain/transport errors and internal failures. A 409 capacity/closure or 429 rate limit does not store a rejected new response. Honor `Retry-After` on 429 or admission 503: admission windows normally return one second; the per-collection minute limiter returns 60 seconds. During a recovery fence, destructive response, retention and workspace operations return `erasure_source_fenced` with 503 before committing a deletion; retry later through the same authenticated operation.

MCP and CLI HTTP failures expose `{error:{code:"http_error",status,operation,message}}` with a fixed local message. They deliberately discard upstream error bodies, which may contain secrets or HTML. Use `status` for automation and the API’s documented code set when integrating directly. MCP schema failures use `invalid_request`; unexpected successful payloads use `invalid_response`. Local transport/authentication/CLI-argument failures are separate from HTTP failures. MCP returns `isError:true`; CLI exits nonzero with no successful JSON on stdout.

After a timeout or 500, a write may have committed. Only retry operations that support an idempotency key with the same key and byte-equivalent semantic payload. After 409, inspect current state before choosing a new key. Do not automatically retry token issuance, publication, deletion or refunds with a fresh key. No tool sends survey invitations or distributes respondent links.

## Deliberate transport exceptions

- **GET /health** — Operational storage health probe, not a tenant capability.
- **GET /internal/metrics** — Private monitoring endpoint with a separate secret.
- **GET /.well-known/oauth-protected-resource** — OAuth resource discovery used before an authenticated capability call.
- **OPTIONS /.well-known/oauth-protected-resource** — Browser CORS preflight for public OAuth resource discovery.
- **OPTIONS /v1/collections/{id}** — Browser CORS preflight; the collection capability remains GET.
- **OPTIONS /v1/collections/{id}/responses** — Browser CORS preflight; submission remains POST.
- **POST /v1/browser/bootstrap** — First-party Clerk session bridge for personal workspace bootstrap and status; not an MCP/CLI capability.
- **POST /v1/browser/oauth-grants** — Interactive owner consent bridge for registered OAuth clients; not an agent-callable capability.
- **GET /v1/browser/service-credentials** — First-party owner dashboard lists agent credential metadata without exposing bearer tokens.
- **POST /v1/browser/service-credentials** — First-party owner dashboard issues a scoped agent token once; the equivalent management capability remains available to API, MCP and CLI clients.
- **DELETE /v1/browser/service-credentials/{id}** — First-party owner dashboard revokes a selected agent credential; the equivalent management capability remains available to API, MCP and CLI clients.

This reference covers implemented local operations. Hosted delivery and any later release capabilities have separate release gates.
