## What to send

Include your workspace ID, SDK/client and version, timestamp with time zone, operation/error code and a short description of expected and actual behavior. A redacted request ID or purchase reference can help. For retries, tell us whether the same idempotency key and payload were preserved, without posting credentials or respondent answers.

Never send passwords, OTPs, payment-card details, access tokens, collection credentials or raw survey responses in a support message. Provide a minimal example with invented data. We will verify owner authority before account/billing changes or customer-data disclosure; support should not require a password or OTP.

## If access may be compromised

Use available account controls to revoke affected agent/service credentials or collections and contact the security route above. Preserve relevant timestamps and redacted request IDs. Do not attempt to investigate by accessing other customers' information. [OWNER: approve the vulnerability-reporting scope and any safe-harbor terms before publishing them.]
