# Disposable supervised process-loss fixture

Candidate for one temporary **Free Render web service plus separate Free Render PostgreSQL 16**. See the [Free service limits](https://render.com/docs/free) and [compute sizes](https://render.com/docs/compute-plans); free compute still consumes included bandwidth/build allowance. It contains no provider resource creator and is excluded from the production Docker context. Parent/operator resource review and exact Free-plan readback remain mandatory before deployment. This fixture proves nothing about production VM loss, persistent disks, availability, Clerk onboarding or distributed admission.

The runtime is copied without recompilation from public community-v0.1.2, source `2996ebcbb9821cff67e0a6e8cae4722f0abf9e42`, image digest `40042f29d15f7fb18a1d95287b099fd94cf2185df3c637e3304d73764488ae7c`. The pinned Node22 Bookworm amd64 base resolves the released binaries' dynamic libraries. API and worker SHA-256 values are embedded at build, checked at startup, and exposed only through authenticated status. There is no production runtime patch, command executor, SQL endpoint or caller-selected proxy target.

A separate database on the production Neon branch is insufficient credential isolation: the released worker requires the literal role `likerts_webhook_worker`, and database roles are shared across that branch. This fixture instead needs an independent fresh PostgreSQL cluster with its own passwords. Never reuse, rotate or grant access to the production worker role.

## Controls and bounds

- Node runs as UID 10001 and starts the unchanged API/worker as children. API binds only `127.0.0.1:18081`; the supervisor listens on the provider's `PORT`.
- `GET /healthz` is public and reports only supervisor liveness. It is not application/database readiness.
- Other routes require `X-Likerts-Drill-Authorization: Bearer <independent 32-byte hex secret>`. Never put this token in a URL or command argument.
- `GET /drill/status` reports a fresh boot ID, expiry, provider service/instance metadata, binary hashes, child PID/start ticks/generation, bounded lifecycle events and cgroup memory counts. Verify all expected identities before any signal.
- `POST /drill/kill` accepts exactly `{target,bootId,generation,pid,startTicks}` with `target` equal to `api` or `worker`. It checks the current child executable path, UID, PID greater than 1 and start ticks immediately before signaling that child. Each target can be killed only once per fixture boot. A confirmed requested `SIGKILL` restarts exactly one replacement child. Unknown exits do not enter a crash loop. The checks narrow PID-reuse risk; they are not an atomic pidfd operation.
- `/api/v1/...` bridges only to the fixed loopback API. Ordinary `Authorization` is forwarded; the drill administrator header is removed. No caller can supply a target host, binary, environment or SQL command to the supervisor. Normal authenticated API endpoints retain their own input and scope checks.
- Eight connections, bounded headers, 1 KiB/three-second kill body, 64 KiB API input, and 15-second upstream inactivity timeout. The API's existing body/output limits also apply. The fixture shuts down after 30 minutes; SIGTERM stops its children with a bounded 27-second fallback. Any supervisor/provider replacement changes the boot ID and invalidates the current drill.
- Child environments are explicit allowlists: API gets only its own DB credential and fixture signing keys; worker gets only its restricted DB credential and webhook key. Neither gets the administrator token, migration-owner DSN or provider credentials. Child stdout/stderr is discarded; status records only fixed lifecycle fields.

## Runtime configuration

Generate independent credentials outside the service. Set `DATABASE_URL` for `likerts_runtime` and `LIKERTS_WEBHOOK_DATABASE_URL` for `likerts_webhook_worker`, both pointing to the exact fresh `LIKERTS_DRILL_DATABASE_HOST` and a database named `likerts_drill_<16–32 lowercase hex>`, also set as `LIKERTS_DRILL_DATABASE`. Both roles must be LOGIN NOINHERIT NOBYPASSRLS NOCREATEDB NOCREATEROLE without memberships; the migrator alone owns schema/tables. Apply the released migrations and exact role provisioning externally before service startup. Never inject owner credentials into the fixture service.

Use `sslmode=verify-full` on a verified external hostname. Render's internal PostgreSQL hostname uses provider-supported `sslmode=require`; that form is accepted only for an exact configured `dpg-*` internal host. It encrypts transport without the external hostname-verification guarantee. The local check alone uses `LIKERTS_DRILL_LOCAL_TEST=1` with `sslmode=disable` on its private Docker network. Do not set that flag on Render.

Also set `LIKERTS_DRILL_ADMIN_TOKEN` to 64 random lowercase hex characters and two separately generated base64-encoded 32-byte values: `LIKERTS_WEBHOOK_CREDENTIAL_KEY` and `LIKERTS_COLLECTION_CREDENTIAL_KEY`. No existing production key is needed. The service uses a fresh hashed, expiring service credential seeded externally in the isolated DB.

This disposable API explicitly sets `LIKERTS_ALLOW_DEV_AUTH=1`, `LIKERTS_DEV_TOKENS={}` and `LIKERTS_ADMISSION_MODE=disabled`. It uses durable PostgreSQL and ordinary scoped service credentials; no development token is configured. Anonymous denial must be verified. This configuration deliberately excludes production `start.sh`, Redis admission, Clerk/OIDC and H01/H05 claims. Exports use temporary local files: process restart can preserve them, but container replacement cannot.

## Local commands and evidence

```sh
DOCKER_BUILDKIT=0 docker build --platform linux/amd64 -t likerts-h06-supervisor:local infrastructure/failure-fixture
node --test infrastructure/failure-fixture/supervisor.test.mjs
python3 infrastructure/failure-fixture/check-local.py
```

`check-local.py` uses a uniquely named PG16 container/network and a separate web container hard-limited to 512 MiB, no swap and 0.1 CPU. It applies actual released migrations, exact restricted-role grants and a real hashed service credential. It checks anonymous/admin denial, one accepted response plus identical retry, wrong-PID rejection, each child's SIGKILL exit/replacement, repeated-signal rejection, persisted response readback and a one-response export. It removes only its own resources. It configures no callback endpoint and contacts no hosted receiver/provider API.

The current desktop is ARM64; the public binaries are amd64. The local check mounts `local-emulation.mjs` solely to accommodate `/proc/<pid>/exe` reporting QEMU for emulated children. That adapter is excluded from the hosted build context and does not weaken the hosted guard. Its memory result includes emulation overhead and is not a native Render memory guarantee. Native Linux ARM64 tests separately exercise the real executable/UID/PID/start-tick guard against an owned native child; native hosted amd64 must still verify the real released executable paths before any signal. See `local-evidence.json` for exact measured counts, hashes and limits. Local idle-child loss/persistence is not an in-flight lease proof.

## Concrete hosted sequence

1. Confirm sufficient free compute/database allowance and included usage. Explicitly create only the approved Free web and Free PG16 resources, with fresh names/credentials; verify returned plan, region, resource IDs and database isolation. Use provider hostnames, no new custom domain, no paid fallback. Keep an exact resource cleanup manifest. Migrate/provision externally, then remove owner material from the deployment environment.
2. Deploy this fixture image/context and verify service identity, boot ID, both native child paths/hashes/PIDs/start ticks, restricted roles, anonymous denial and a scoped service-credential lifecycle. Do not signal if a child is PID1, mismatched, exited or replaced. Discard the run if the provider restarts the supervisor.
3. For callback loss, configure one fresh disabled `response.accepted` endpoint, install its key on the separately isolated [signed receiver](../acceptance/receiver/README.md), and enable it. Use its already-tested eight-second first-receipt hold. This bounded fixture uses survey version 1; the current receiver has a narrower 32-bit version cap than the API database's bigint representation, so this does not claim arbitrary-version receiver compatibility. Observe both its authenticated marker and the exact running DB attempt/lease. Signal only the matching worker child before the hold ends. Poll at most every two seconds for 180 seconds; require the same delivery/event, old attempt `expired`/`worker_lease_expired`, a new delivered attempt/204 and one distinct receiver event. A normal transport retry is not this proof.
4. For a deterministic API-export loss window, the isolated DB controller can hold a short transaction with `LOCK TABLE likerts.survey_versions IN ACCESS EXCLUSIVE MODE`. `create_export` and `claim_export` do not read that table; `export_snapshot` later joins it. Create one export through the fixed API bridge, observe its committed running lease, then signal only the matching API child while snapshot reading waits. Release the controller lock in `finally`, with an independent ~20-second deadline. This is a proposed locking fixture, not executed evidence: validate it locally before hosted use. Do not alter lease timestamps or job status. Poll authenticated export GET across the actual 300-second lease; require a new winning lease in the final object key, correct one-response manifest/SHA and denied unauthorized download. Allow up to 12 minutes after initial lease observation.
5. Disable/revoke synthetic endpoints and credentials before cleanup, preserve only sanitized evidence, stop the web fixture and delete exactly the owned Free web/database resources. Remove receiver key/temporary deployment per its runbook. Confirm production source/deployments/credentials were untouched.

A passing hosted run establishes recovery of the released **application child process** with its PostgreSQL service still alive. It does not establish loss of the Render VM/container, production deployment recovery, a second live replica taking over, database crash recovery or durable local exports across provider restart. A separate Free database also enables a later bounded web rollback test, but that is not proven by a child SIGKILL.
