Durable offline collection is an explicit SDK facility on all five platforms. Queues seal the collection binding, submission, idempotency key, age, size, attempts and state; enforce 1,000-record/10-MiB/seven-day defaults and hard ceilings of 10,000 records, 100 MiB, 30 days and 64 KiB per record; process a stable oldest-first snapshot with one caller-triggered flush; stop before the next attempt on cancellation; quarantine authentication failures; and retain bounded terminal reasons without exposing answers or credentials. Conditional visibility is implemented as schema version 3 across the backend and all five SDK renderers. Each question may contain one typed `visibleWhen` predicate using equality, multiple-choice inclusion or answered state; draft validation rejects invalid/self references, incompatible source/operator/value combinations and cycles. Comparisons are false without an effective source answer, answered text is trimmed, and hidden sources count as unanswered. Renderers recursively remove answers as questions become hidden, while the backend independently discards hidden answers before requiredness/value validation and persistence. The shared fixtures pass Web, React Native, Swift, Android and Flutter tests plus real API/MCP/CLI/Web integration; invalid visible required submissions remain unbilled. See `contracts/CONDITIONAL-VISIBILITY.md`.

Pages and bounded forward branching are implemented as schema version 4. Pages partition every question exactly once, reuse typed visibility predicates for ordered forward-only branches, and reject unknown, backward, duplicate and future-dependent routes. Web, React Native, Swift, Android and Flutter expose the same physical current/total plus visited progress contract; their built-in renderers show only the current reached page, follow actual Back history, validate before advancing, recompute and prune answers when a route changes, and submit only routed answers.
